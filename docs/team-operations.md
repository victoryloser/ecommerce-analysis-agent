# 团队实例运维

## 安装与健康检查

使用指定提交构建的源码压缩包，保留 `MANIFEST.json` 和同名 SHA-256 文件。按项目安装说明创建 Python 3.11 环境，安装 `requirements.lock.txt`，再用 `pip install --no-deps -e .` 安装源码。发布者可用以下命令构建并验证固定版本。[安装说明](../README.zh-CN.md#安装与启动)

```powershell
python scripts/build_release.py --commit <完整提交SHA> --output dist/team-release.zip
python scripts/verify_release.py --archive dist/team-release.zip
```

网页与工作进程使用同一个 `ANALYSIS_INSTANCE_DIR` 和独立部署的 `.env`。启动后用 `Invoke-RestMethod http://127.0.0.1:7860/healthz` 检查网页及任务数据库。管理员在“实例运行状态”查看工作进程、模型配置与最近的模型结果，以及最近成功快照和导入任务。点“测试模型连接”会向配置的模型发出一条固定测试消息。

默认同时执行三个团队交互请求，`TEAM_ANALYSIS_CONCURRENCY` 可按实例容量调整。同一会话的操作按服务器收到请求的顺序执行，网页也会按提交顺序发送。会话已保存的分析步骤可从历史打开，点“继续未完成分析”。工作进程每次执行一个后台任务。手工导入、完整 CSV 导出、批量周报以及因确认交付触发的周报修订，均可在“后台任务”重新打开。

- 同一来源、父快照、文件及映射的重复导入复用已发布快照。中断在发布前的导入从头执行，发布后恢复只登记同一结果。手工接入完成时可主动切换到新快照。
- 完整导出固定到提交时的查询证据与快照。同一账号对同一证据重复提交时，会复用有效任务或下载。下载时复核当前授权。
- 下载链接到期后，导出的 CSV 仍保存在实例的 `runs/` 下。失败或取消的导入会保留待重试的上传文件。长期运行时，需和客户约定这些文件的留存期，并把磁盘占用计入备份容量。
- 周报批次逐期保存。执行中的周报可在当前期结束后取消，重试从未完成期继续。导入与导出可在排队时取消。已失败或取消的任务可重试，工作进程重启时会恢复中断任务。
- 运维统计按 UTC 日聚合。时延以毫秒记录，模型提供用量时统计 token。周报计算复用已保存的计划，出报阶段使用零模型调用。运维记录使用任务或会话标识定位，查询证据和来源仍从业务入口查验。

## 备份和恢复

停止实例网页进程、后台工作进程及其他写入该实例的导入和维护命令。把备份放到独立磁盘或约定的备份位置。先确认管理员权限，再执行。

```powershell
.venv/Scripts/python.exe -m app.team_backup backup --instance D:\analysis-instances\pilot --output D:\analysis-backups\pilot-before-upgrade.zip
.venv/Scripts/python.exe -m app.team_backup restore --archive D:\analysis-backups\pilot-before-upgrade.zip --instance D:\analysis-instances\pilot-restored
```

备份记录源码指纹，并为 `data/`、`runs/` 中的快照、来源、映射、会话、权限、任务、周报及证据文件生成指纹。SQLite 使用一致备份。备份和恢复时均按已发布的快照清单核对数据库和来源文件。旧快照声明的工程内来源原件也会随备份归档。恢复还会检查归档文件、逐项指纹和 SQLite，完成后生成新实例目录。部署人员在新位置单独配置 `.env`。独立交付目录需由数据团队另行保留。

用备份对应的源码版本先启动恢复实例。以原读者身份访问已保存的固定周报链接，核对版本、期间与金额。使用有明细权限的账号查看一笔来源记录，再执行一条新分析并核对新证据指纹。将数据丢失窗口和恢复耗时记入试点报告，由客户确定可接受目标。

## 升级与回退

升级前保留已验证的旧版压缩包和同一时间点的实例备份。在恢复出的新目录安装候选版本并启动，检查健康状态、任务恢复、角色访问、历史周报和新分析。候选通过后，再将网关指向新实例。回退时在单独目录用旧版源码和升级前备份启动，核对同样的访问和报告后切回。切换时应暂停写入，并将可能涉及的切换后流水纳入回退记录。

## 发布验收

比赛兼容与客户试点各保留一份验收记录。比赛验收绑定提交、模型配置和快照哈希，运行现有 D1–D4 连续评测和原入口回归。客户验收使用该客户月档和独立财务汇总，检查权限、跨期退款、周报修订、待核实单和恢复。负载验收以同机单会话和五会话各二十回合对照，同时导入一份月档，记录浏览器提交到结果的中位数与 P95，以及服务端排队、模型和查询时长。上线前记录差额原因、运行失败、恢复耗时和复验结果。[复赛评测流程](round2-evaluation.md)
